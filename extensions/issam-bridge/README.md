# 아이쌤봇 연결 (issam-bridge)

아이쌤봇이 맡긴 일을 **선생님 본인 크롬**에서 처리하고, 결과를 대화로 돌려보내는 확장 프로그램 쪽 코드입니다. 서버 쪽은 이 저장소의 `packages/core/src/browser-device.ts`, `apps/api/src/browser-device.ts`, `apps/web/src/components/BrowserDeviceSettings.tsx` 에 있습니다.

## 왜 별도 폴더인가

확장 프로그램(한밭 도우미)은 이 저장소의 일부가 아니라 **빌드된 결과물**로 전달됩니다. 그 빌드 안의 `enhancements/` 폴더가 이미 손으로 쓴 오버레이이고, 여기 있는 파일들은 거기에 한 겹 더 얹히는 것입니다. 그래서 pnpm 워크스페이스 패키지가 아니고, 빌드 단계 없는 순수 ESM입니다.

## 적용

```bash
# 한밭 도우미 zip 의 압축을 푼 폴더를 지정합니다
node extensions/issam-bridge/apply.mjs ~/Downloads/hanbat-agent
```

하는 일:

| | |
|---|---|
| 복사 | `enhancements/issam-bridge.mjs`, `enhancements/issam-bridge-ui.mjs`, `issam.html` |
| `enhancements/runtime.mjs` | 설치 경로 `installIssamAndMobile` 추가 |
| `background.js` | 에이전트 핸들을 휴대폰 경로와 아이쌤봇 양쪽에 전달 |
| `background.js` | 실행 기록을 아이쌤봇 쪽에도 전달 (에이전트의 최종 답이 여기에만 있습니다) |
| `enhancements/workspace.mjs` | 사이드패널에 ‘🤖 아이쌤봇 연결’ 버튼 |

**권한은 하나도 추가하지 않습니다.** 매니페스트는 건드리지 않습니다.

편집은 전부 정확한 기준 문자열에 걸려 있고, 그 문자열이 **정확히 한 번** 나오지 않으면 아무것도 바꾸지 않고 멈춥니다. 확장을 새로 빌드해서 기준이 사라지면 조용히 아무것도 안 하는 대신 요란하게 실패합니다. 두 번 실행해도 안전합니다.

새 빌드가 나오면 압축을 풀고 다시 한 번 실행하면 됩니다.

## 연결

1. 아이쌤봇 설정 → **내 크롬에 일 맡기기** → 이름을 적고 **크롬 연결**
2. 한 번만 보이는 **연결 코드**를 복사
3. 사이드패널 → **🤖 아이쌤봇 연결** → 코드 붙여넣기 → **연결**
4. 아이쌤봇 설정에 **켜져 있음** 으로 보이면 끝

코드 안에 토큰이 들어 있습니다. 암호가 아니라 운반 수단이니, 코드 자체를 토큰처럼 다루세요.

## 동작

확장이 몇 초마다 서버에 **물어봅니다.** 반대 방향은 없습니다 — 크롬 확장에는 바깥에서 연결할 수 없고, MV3 서비스 워커는 몇 초만 놀아도 종료되기 때문에 오래 열어두는 연결은 전부 거짓말이 됩니다. 폴링은 잠든 노트북에서도 살아남는 유일한 방법입니다.

그래서 **단계가 아니라 작업 전체를 넘깁니다.** `이동` → `화면 읽기` → `클릭` 을 3초 간격으로 왕복시키면 한 번에 끝날 일이 몇 분이 됩니다. 봇이 선생님 말로 된 지시 하나를 적고, 확장의 에이전트가 그것을 수행하고, 결과 하나가 돌아옵니다.

끝나면 결과가 아이쌤봇 대화에 올라가고, 작업 폴더를 연결해 두었으면 그 안 `아이쌤봇/` 에 기록이 남습니다 (`2026-10-26_153012_성적표.md` 꼴).

## 정한 것들

**기본값은 요청마다 승인입니다.** 이 브라우저는 학교 업무 시스템에 이미 로그인돼 있습니다. 서버가 시켰다는 이유로 실행되지 않고, 선생님이 보고 **실행**을 눌러서 실행됩니다. 화면에서 어느 탭에서 돌릴지도 고릅니다.

**승인 없이 실행하는 모드는 있고, 꺼져 있습니다.** 수업 중에도 일이 진행되는 대신 로그인된 브라우저에서 무엇을 할지 먼저 보지 못한다는 것을, 켜는 화면에서 그대로 적어 두었습니다.

**이미 손댄 작업은 다시 실행하지 않습니다.** 작업 중에 크롬이 죽으면 다음에 켜졌을 때 "중단됐습니다, 직접 확인하세요"라고 알리고 끝냅니다. 어디까지 갔는지 아무도 모르는 일을 다시 돌리는 것이 가장 위험합니다.

**끝난 일의 결과는 네트워크가 끊겨도 버리지 않습니다.** 저장해 두었다가 다음 폴링에 보냅니다. 그러지 않으면 실제로 성공한 작업이 "크롬이 멈췄습니다"로 돌아갑니다.

**401은 한 가지 뜻으로만 읽습니다.** 서버는 모든 인증 실패에 똑같은 401을 주므로, 이쪽이 아는 것도 "이 연결은 더 이상 동작하지 않는다" 하나뿐입니다. 503 같은 서버 오류로는 연결을 끊지 않습니다.

**이 확장의 페이지가 아니면 응답하지 않습니다.** 웹 페이지가 승인 메시지를 보낼 수 있으면, 로그인된 브라우저에서 임의의 작업을 통과시킬 수 있습니다.

## 테스트

```bash
npx vitest run extensions/issam-bridge/src/issam-bridge.test.ts
```

연결 코드 해독은 서버 쪽 `encodeBrowserDevicePairing` 을 직접 불러서 맞춰봅니다. 양쪽이 각자 구현하고 있어서, 어긋나면 선생님이 그냥 연결을 못 합니다.

브라우저 안에서의 실제 동작(확장 로드 후 폴링·승인·실행)은 **아직 크롬에서 확인하지 않았습니다.** 위 순서대로 로드해서 확인이 필요합니다.
